---
description: Audit dotfiles deployment, safely apply missing Stow links, and verify the result
argument-hint: "[packages or scope; default: current-machine profile]"
---
Audit and apply my dotfiles configuration. Requested scope: ${ARGUMENTS:-the documented profile for this machine}.

1. Locate the dotfiles checkout (normally `~/dotfiles`) and read its README, applicable AGENTS.md files, maintenance documentation, and Stow ignore rules. Inspect Git status; preserve all existing edits and untracked files. Determine the documented package profile for this OS and local/SSH environment. Ask if the requested scope or deployment target is ambiguous.
2. Audit before changing anything. Run the applicable built-in checks, but do not equate a successful Stow conflict check with complete deployment. Inventory tracked and untracked source files with NUL-safe paths, honor Stow's effective ignore rules, and compare each deployable file with its expected home-directory target using file identity (including files reached through directory symlinks). Distinguish missing links, broken links, conflicting files, and intentionally excluded runtime/development state. Do not print credentials or private state.
3. For the selected packages, run a verbose Stow simulation against the intended home directory. Follow the documented deployment flags; Pi requires `--no-folding`, with `~/.pi` and `~/.pi/agent` remaining real local directories. Stop if there are sync conflicts, deployment conflicts, unexpected symlink targets, or unsafe state-directory links. Report the issue and ask before resolving it. Never use `--adopt`, delete or overwrite existing files, or move local state to make deployment succeed.
4. If the simulation is conflict-free, deploy the selected packages with GNU Stow using the verified source and target directories. This invocation authorizes missing-link deployment only, not config edits, dependency installation/upgrades, commits, or unrelated repairs. Do not reload or restart running applications automatically.
5. Repeat the file-by-file deployment audit and applicable checks. For Pi, verify that configured local packages and their declared resources exist at the deployed paths, and that auth, sessions, downloaded packages, and dependencies remain machine-local. Check live application settings where read-only inspection is available; otherwise mark them unverified. If inspecting Homebrew dependencies, disable automatic updates and distinguish missing dependencies from available upgrades.
6. Summarize what was already deployed, what changed, failures/skips, and remaining dependency or runtime gaps. Clearly distinguish linked files, successful startup/tests, and settings confirmed in running apps. Give the required manual reload/restart instructions; newly linked files alone do not prove the current process loaded them.
