# 证据与取舍（沿用 v0.1）

来源归属、客观正确性、回答解释程度是三件事。

| 内容标记 | 含义 |
|---|---|
| User-expressed | 用户在 Sources 或真实回答中明确表达过；兼容旧 User-confirmed，但不暗示掌握 |
| AI-supplemented | AI 的命名、补充、推导、例子、查证；不得倒填为用户理解 |
| Unresolved | 歧义、未解释步骤、尚待核实的主张；独立于是否被用户说过 |
| Correction | 有证据反驳原主张，必须保留原义、定位、修正和依据；不是仅因措辞不同而纠错 |

知识正文可以自然综合不同来源，用稳定 Claim ID 指向末尾对应表；表中按子主张拆分混合归属，不把整段升级为用户理解。学习状态与来源叙述移至辅助层，技术限定仍留正文。需要时仍可用局部行内标记。Correction 可以与 User-expressed 同时存在；原错误表达、来源和修正依据保留，不因正文改写而消失。

关键词只支持“提过”，不支持解释。例如 `Functor law` 不证明知道定律；三步骤只支持记过流程，不证明推导过位置公式。外部资料核实的是事实，不是用户是否理解。历史回答与本轮新回答分别定位；相互矛盾时并列保留、评估，不用最新一句泛泛“对”消除冲突。

取舍延续：跨题机制/方法优先；进度、孤立接口名、缺症状的错误清单暂缓；相邻段落不构成因果关系。S4“代码错误”不能擅自绑定 Find Repeats。题意未知时改用通用示例并明确假设，不补题目规格。按 slug 去重，内容冲突保留双方。不遍历全库自动建链接；每个关联必须说明具体联系与目标是否存在。
