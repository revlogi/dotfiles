# 选题、停止与答案评估

## 从缺口到问题

每个候选记录：来源位置、缺失的关系、内部类别、影响的笔记主张、是否依赖其他回答、优先级、成本。内部类别可重叠：Context Reconstruction（指代/问题情境）、Mechanism Clarification（因果机制）、Reasoning Reconstruction（选法推理）、Generalization（迁移条件）、Misconception Detection（具体混淆）、Understanding Boundary（理解边界）。不用让用户分类。

先删除无法指向具体 Sources、纯术语定义、可查证事实、只为填模板而问的候选。剩余按以下顺序排序：
1. 不澄清就会歪曲用户理解/任务含义；
2. 方法最关键的推理桥梁；
3. 会改变 Trigger/Transformation/Method；
4. 概念边界、复用条件或可定位的混淆。
同级优先回答负担小、能解决多个相关缺口的题；语义重叠只留一题。已有真实历史回答支持的关系不重问。每批初始最多四题，可为 0 或 1；无问题时记录来源已充分/仅暂缓而无需澄清的理由。

## 出题自检

问题须锚定原句/实例；问一个缺失的 Why/How，必要时先恢复 What 指代。给出具体回答范围和允许不知道的出口。不得把目标结论或证明塞进问题；可给输入和已知前提。若提供提示后用户只重复提示，不能算独立解释。只问会改变笔记内容/归属的问题。

反例“什么是 Exclusive Scan”改为“你记了 scan → scatter：为什么前者能给后者目标位置？”；反例“请解释 CUDA”改为“这条异步调用链里，你当时凭什么判断 host 能读结果？”；反例“Functor 有什么用”改为“原文列的三个实例，你用哪个共同特征联系它们？选最有直觉的一个说明。”

对函数实例，不先告知 `fmap g h = g . h` 再问为什么（除非等式本来就来自用户）。可以给 `h :: r -> a`、`g :: a -> b`，让用户说明如何得到 `r -> b`；只在已回答实例直觉后、仍有关键缺口时追问。

## 停止

初始 0–4 题；全批最多一次追问轮，最多两题。追问仅针对实际回答暴露的关键缺口，写明依赖的 Q/回答 ID。答错不自动无限加题。已经解释、只剩小细节、明确不知道/跳过/疲惫时停止提问；这些状态不是失败，也不是掌握。
取消、超时、调用失败或无回复：保存 pending/cancelled/error，暂停依赖回答的工作，不默认为跳过。已提交的显式跳过可结束澄清并生成保留 Open Questions 的 provisional 草稿。若“结束”是取消整个任务，则只保存状态，不继续生成。

## ASSESS（不打分）

逐条保存原文和：是否回应问题、有效关系/推理、正确性与依据、已解释部分、可复用主张、残留缺口、下一步。

| 判断 | 标准与处理 |
|---|---|
| Explained | 用自己的表达解释了核心关系；只提升该关系，补充公式/证明仍归 AI |
| Partial | 部分解释成立但缺关键连接；可针对性追问，不能提升整段 |
| Unclear | 指代或因果不清；不以措辞不一样判错 |
| Incorrect | 可定位的错误，有可靠依据；保留原话并另标 Correction |
| Skipped | 用户明确跳过或工具明确 skipped；保留未决 |
| Unknown | 用户明确不知道/不记得；结束该题，不继续逼问 |

从未收到回答时是 Pending，不填 Unknown。裸结论正确但无要求的推理通常 Partial，不直接 Explained；“因为前面有几个有效项”虽简短但解释了位置含义，可为 Explained。正确性核验和这些判断分栏。只用关键词与 AI 预期措辞匹配不是评估。
