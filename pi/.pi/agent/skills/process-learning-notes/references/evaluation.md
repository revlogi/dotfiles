# 评估方法（v0.3，保留 v0.2 交互评估）

每次报告区分“真实 live 交互”“用户提供历史回答回放”“静态规则审阅”“未验证”。不伪造工具结果，不把 accepted 当成功答案。优先复用真实小批材料，无需建立测试框架。

A：比较旧问题与新问题，说明新问题改变哪条主张、是否暗示答案、是否依赖已知回答；允许保留旧的好问题。
B：检查实际可调用工具、发问、真实返回、保存、ASSESS、再综合；任一环节未发生就标未完成。Pi 与其他宿主分别报告。错误/取消处理若只是走查不得写成真实测试通过。
C：三篇案例检查机制、Usage/Trigger、例子、归属、Recall 和篇幅；知识模块不能被来源标签替代。
D：用 examples.md 的 H2 作为历史回放；部分理解只提升局部主张，未答追问不提升传播规则。
E：仅关键词不推出 laws 理解；先选一题或暂缓，未获预览授权不自动展开完整笔记。

恢复走查：有 pending 时不重复发问；有原始答复无 assessment 时重做评估；cancelled/error 不升级；缺原始记录引用时停止。所有走查说明不是生产交互验证。

## v0.3 知识提炼评估

复用同一 Sources 和真实 Answers，不制造新交互或升级原评估。分别抽取旧/新 Core Idea 作对比，不用不同证据解释质量提升。

1. 独立阅读：遮住 Learning State/Provenance，Core Idea 是否仍准确、简洁、有解释力？通常 1–2 句；长度不代替语义判断。
2. 连贯性：把每节对照核心关系，机制/例子/使用条件是否服务同一中心？若拆分，说明内容去向，不能静默删知识。
3. 归属完整性：核心、公式、例子、限定等重要主张能否回溯？一句混合 User-expressed/AI 时是否拆到子主张？从表返回正文能否精确定位？
4. 理解边界回归：相同实际答案的 Partial/Explained 范围是否维持；没有解释 laws 不能因新正文准确就标掌握。
5. 输出简短的对比、边界理由和仍存问题，不写冗长评分报告。不把查禁用词的静态检查当作语义质量已证实。
