# Neovim Configuration Guide

## Layout

- `init.lua`: entry point; loads configuration modules in startup order
- `filetype.lua`: custom filetype detection rules
- `after/ftplugin/`: filetype-specific indentation, options, and buffer-local keymaps
- `lsp/`: native `vim.lsp.config` non-default server overrides
- `lua/revlogi/config/`: editor settings, keymaps, autocmds, autosave, commands, and native package setup
- `lua/revlogi/plugins/`: ordinary Lua modules that configure plugins at startup
- `lua/revlogi/utils/`: reusable helpers, including platform and remote-session detection
- `lua/revlogi/health.lua`: custom health checks (`:checkhealth revlogi`)
- `nvim-pack-lock.json`: native plugin lockfile; generated by Neovim

## Validation

```bash
stylua --check .
nvim --headless +qa
nvim --headless "+checkhealth revlogi" +qa
nvim --headless "+luafile tests/smoke.lua" +qa
```

## Style

- Use two-space indentation, single quotes, and a 160-column limit.
- Use `vim.pack` with an explicit package list and eager loading; do not add lazy loaders or spec wrappers.
- Plugin modules call setup functions and define mappings directly. Keep their load order explicit in `revlogi.config.pack`.
- Use `require 'module.name'` for simple imports.
- Use `snake_case` for Lua names and descriptive `desc` values for keymaps.
- Keep platform-specific behavior behind `revlogi.utils.platform` checks.
- Add an `lsp/<server>.lua` module only when overriding the server's default configuration.
