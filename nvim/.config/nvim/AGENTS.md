# Neovim Configuration Guide

## Layout

- `init.lua`: entry point; loads configuration modules in startup order
- `lua/custom/config/`: editor settings, keymaps, autocmds, commands, and native package setup
- `lua/custom/plugins/`: ordinary Lua modules that configure plugins at startup
- `nvim-pack-lock.json`: native plugin lockfile; generated by Neovim
- `lua/custom/utils/`: reusable helpers, including platform and remote-session detection
- `lua/lsp/`: shared LSP utilities and non-default server overrides
- `lua/dotfiles/health.lua`: custom health checks

## Validation

```bash
stylua --check .
nvim --headless +qa
nvim --headless "+checkhealth dotfiles" +qa
nvim --headless "+luafile tests/smoke.lua" +qa
```

## Style

- Use two-space indentation, single quotes, and a 160-column limit.
- Use `vim.pack` with an explicit package list and eager loading; do not add lazy loaders or spec wrappers.
- Plugin modules call setup functions and define mappings directly. Keep their load order explicit in `custom.config.pack`.
- Use `require 'module.name'` for simple imports.
- Use `snake_case` for Lua names and descriptive `desc` values for keymaps.
- Keep platform-specific behavior behind `custom.utils.platform` checks.
- Add an LSP module only when overriding the server's default configuration.
